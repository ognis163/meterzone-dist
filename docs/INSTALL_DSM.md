# Установка MeterZone на Synology DSM 7

Полная инструкция: от пустого NAS до работающего приложения.
Компилировать ничего не нужно — используется готовый образ с GitHub.

## Что нужно

| Требование | Как проверить |
|---|---|
| DSM 7.x | «Панель управления» → «Информация о системе» |
| Пакет **Container Manager** | «Центр пакетов» → «Все пакеты» → поиск `Container Manager` |
| Свободный порт | по умолчанию 8099 |
| Доступ к `ghcr.io` | проверка ниже, в разделе «Если образ не скачивается» |

Если Container Manager не установлен — установите из «Центра пакетов».
В DSM 6 он назывался Docker; инструкция для 7.x.

## Шаг 1. Папка на NAS

Откройте **File Station** и создайте две папки:

```
/volume1/docker/meterzone          ← папка проекта
/volume1/docker/meterzone/data     ← папка данных, обязательно
```

> Папку `data` создайте руками. Synology не создаёт её автоматически,
> и без неё контейнер упадёт с ошибкой
> `Bind mount failed: '/volume1/docker/meterzone/data' does not exist`.

## Шаг 2. Файл конфигурации

Скачайте [`docker-compose.yml`](../docker-compose.yml) из этого репозитория
и положите в `/volume1/docker/meterzone`.

Получится:

```
/volume1/docker/meterzone/
├── docker-compose.yml
└── data/
```

Внутри файла менять ничего не обязательно. Основное, что там задано:

| Параметр | Значение | Что значит |
|---|---|---|
| `image` | `ghcr.io/ognis163/meterzone-dist:latest` | готовый образ |
| `ports` | `8099:8099` | порт на NAS : порт в контейнере |
| `APP_DB` | `/data/meterzone.db` | файл базы |
| `APP_BACKUP_DIR` | `/data/backups` | резервные копии |
| `TZ`, `APP_TZ` | `Europe/Astrakhan` | часовой пояс |
| `PORT_FIXED` | `1` | порт меняется только здесь, не из интерфейса |

Свой часовой пояс можно посмотреть в «Панели управления» → «Регион» →
«Формат времени».

## Шаг 3. Создание проекта

**Container Manager** → раздел **Проект** → **Создать**.

| Поле | Значение |
|---|---|
| Имя проекта | `meterzone` |
| Путь | `/volume1/docker/meterzone` |
| Источник | **Использовать существующий `docker-compose.yml`** |

Нажмите **Далее** → **Готово**. DSM скачает образ (~16 МБ) и запустит
контейнер. Первый запуск занимает до минуты, дальше — секунды.

В списке проектов у `meterzone` должен появиться статус **Выполняется**.

## Шаг 4. Проверка

Откройте в браузере:

```
http://адрес-NAS:8099
```

Должна открыться главная страница с предложением создать объект.

Проверка без браузера (SSH):

```sh
curl http://127.0.0.1:8099/healthz
```

Ответ:

```json
{"ok":true,"version":"1.5","uptime":"12s","db":"/data/meterzone.db"}
```

В File Station в папке `data` после запуска появятся `meterzone.db`
и подпапка `backups`.

## Что дальше

1. **Объекты** → создайте дом или помещение.
2. В объекте добавьте **счётчики**: холодная и горячая вода, электроэнергия.
3. На главной вводите показания — они сохраняются автоматически.
4. **Журнал** показывает расход и начисления за период, **Документы** —
   сведения и ведомости в PDF.

На iPhone сайт добавляется на экран «Домой» (Safari → «Поделиться» →
«На экран Домой») и открывается без панелей браузера.

## Данные и резервные копии

| Что | Где |
|---|---|
| База | `/volume1/docker/meterzone/data/meterzone.db` |
| Копии | `/volume1/docker/meterzone/data/backups/` (14 последних) |

Копия создаётся автоматически раз в месяц и вручную кнопкой
**Настройки** → **Создать копию**. Оттуда же её можно скачать и восстановить.

Приложение само копирует базу в `data/backups`, но эти копии лежат
на том же NAS. Чтобы защититься от поломки диска, добавьте папку
`/volume1/docker/meterzone/data` в задание **Hyper Backup** или включите
дублирование копии на почту в настройках приложения.

## Перенос базы с роутера Keenetic

База открывается как есть, конвертировать нечего.

1. На роутере остановите сервис, чтобы файл был целым:
   ```sh
   /opt/etc/init.d/S99meterzone stop
   ```
2. Заберите файл базы на компьютер:
   ```sh
   scp root@192.168.x.x:/opt/meterzone/data/meterzone.db ./meterzone.db
   ```
   Без SSH: на роутере в приложении «Настройки» → «Создать копию»,
   затем скачайте файл `.db` из списка копий.
3. На NAS остановите проект: Container Manager → `meterzone` → **Остановить**.
4. В File Station удалите из папки `data` файлы `meterzone.db`,
   `meterzone.db-wal`, `meterzone.db-shm`, если они есть.
5. Скопируйте в `data` ваш файл и переименуйте его в `meterzone.db`.
6. Запустите проект: **Выполняется**.
7. Проверьте в приложении «Настройки»: число объектов, приборов и
   показаний должно совпасть с роутером.

Альтернатива без SSH: запустите приложение с пустой базой и загрузите
файл через **Настройки** → **Импорт старой базы**. На пустой базе
результат тот же.

## Обновление

Когда в [MeterZone](https://github.com/ognis163/MeterZone) меняется код,
GitHub Actions собирает новый образ автоматически.

**Через интерфейс:** Container Manager → проект `meterzone` →
**Действие** → **Загрузить образ**, затем пересоздайте проект.

**Через SSH:**

```sh
cd /volume1/docker/meterzone
sudo docker compose pull
sudo docker compose up -d
```

Версия видна в приложении внизу страницы «Настройки» и в ответе `/healthz`.

## Смена порта

Порт задаётся в `docker-compose.yml` в двух местах и должен совпадать:

```yaml
    ports:
      - "8090:8090"
    environment:
      PORT: "8090"
```

После правки: **Действие** → **Построить заново** (или `docker compose up -d`).
Из интерфейса приложения порт не меняется — так сделано специально,
иначе приложение переехало бы на порт, который наружу не проброшен.

## Доступ снаружи

По умолчанию приложение принимает только локальные и частные адреса.
Если открываете его по внешнему IP или через VPN с публичным адресом
и видите «Доступ разрешён только из локальной сети», раскомментируйте
в `docker-compose.yml`:

```yaml
      ALLOW_PUBLIC: "1"
```

Через обратный прокси DSM (HTTPS с сертификатом) запросы приходят
с внутреннего адреса, и `ALLOW_PUBLIC` не требуется.

## Если образ не скачивается

Проверьте по SSH, достаёт ли NAS до GitHub:

```sh
sudo docker pull ghcr.io/ognis163/meterzone-dist:latest
```

| Результат | Что делать |
|---|---|
| `Status: Downloaded` | всё в порядке, пересоздайте проект |
| `denied` / `unauthorized` | проверьте, что репозиторий публичный |
| `TLS handshake timeout`, `no such host` | NAS блокирует `ghcr.io` — настройте прокси/DNS или используйте установку на Keenetic |

## Диагностика

```sh
# контейнер запущен?
sudo docker ps --filter name=meterzone

# журнал приложения (при старте печатает версию, порт, путь к базе)
sudo docker logs --tail 50 meterzone-meterzone-1

# ответ сервиса
curl http://127.0.0.1:8099/healthz

# что лежит в папке данных
ls -la /volume1/docker/meterzone/data
```

При старте в журнале должно быть:

```
MeterZone 1.5 · Europe/Astrakhan
слушаю порт 8099
база: /data/meterzone.db
резервные копии: /data/backups
сервер запущен на http://192.168.x.x:8099
```

## Удаление

1. Container Manager → проект `meterzone` → **Действие** → **Удалить**.
2. Удалите папку `/volume1/docker/meterzone` в File Station.

Перед удалением скачайте резервную копию из приложения, если данные нужны.
